# UEDevTest · 开发文档

## 项目定位

UEDevTest 是 **UE 工具开发的长期学习项目兼简历作品集**，不是单一工具项目：以编辑器工具为核心（后续也会加入客户端相关开发），每个工具以独立插件形式挂在工程 `Plugins/` 下，互不污染。

- **当前阶段切入点：资产审计系统（AssetAudit 插件）**。选它当第一个工具，是因为它同时覆盖 Python、C++、UE 编辑器接口三大学习目标，且与自研引擎的审计工具经验直接同构——学习成本集中在"UE 的名词和坑"，而不是"怎么做工具"
- 后续工具按同样模式扩展：**新工具 = 新插件**，各自带源码与文档，互不依赖

## 文档维护约定

- **本目录是活文档**：随项目开发同步更新，不以"写完"为终点
- **全文不含本机绝对路径**（文档会上传 GitHub）。路径一律用占位符：
  - `<UE_ROOT>` —— UE 5.8 引擎安装目录（Epic Launcher 安装版，安装位置因机器而异）
  - `<ProjectRoot>` —— 本工程根目录（即本文件所在目录的上一级）
- 版本信息只写"版本号 + 来源"，不写盘符
- **UE 编辑器为官方汉化版**：UI 操作步骤一律按「中文文案（英文标识符）」书写，与界面显示一致；代码/配置文件里的标识符保持英文

## 环境事实（已验证）

| 项 | 值 |
|---|---|
| 引擎 | UE 5.8.1（Epic Launcher 安装版，下文记作 `<UE_ROOT>`） |
| 编译器 | Visual Studio 18 Community（含 VC x64 工具链），已验证可编译 UE C++ 工程 |
| 命令行编译 | `"<UE_ROOT>\Engine\Build\BatchFiles\Build.bat" UEDevTestEditor Win64 Development -project="<ProjectRoot>\UEDevTest.uproject" -WaitMutex` |

## 使用建议

1. 顺序：读任务清单第一部分（架构）→ 建工程（阶段 0）→ 按阶段一路做到阶段 8。
2. 每个阶段结束时，用该阶段的"完成标准"验证，全部通过再进入下一阶段；编译不过先看该阶段"接口要点"里的 ⚠ 坑。
3. **开发方式以官方推荐为主**：能用官方向导/工具链完成的（如插件创建向导）就用官方方式；手写代码是学习必需的部分；手动重复机械步骤仅用于理解结构，非必需。允许查官方文档和引擎源码（`<UE_ROOT>\Engine\Source\`），不允许让 AI 代写。
4. 作品集角度：每完成一个阶段就 git commit 一次，提交信息写清做了什么——最终这就是一份可展示的开发历史。
5. **文档与代码同步**：结构变化、接口更名、新增工具时，第一时间更新对应文档，不让文档烂在初始版本。
